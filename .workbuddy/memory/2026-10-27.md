## legado iOS 复刻 —— 打通构建链路

**背景**：上游 `HapeLee/legado-with-MD3`（Android/Kotlin），目标 iOS 原生复刻，
数据层与规则引擎一比一，UI 用 SwiftUI + 液态玻璃。上一阶段已铺了约 10.5k 行 Swift 骨架，
但从未编译通过（385 个错误）。

**依赖换源方案（本机关键约束）**：
- GitHub 直连约 30KB/s，git clone GRDB 十几分钟下不完。
- `xcodebuild` / `swift package` 编译 Package.swift 清单时 fork `sandbox-exec`，
  返回 `sandbox_apply: Operation not permitted`（外层已有沙箱，不允许嵌套）。
  但 `swift build --disable-sandbox` 正常。
- 最终方案：`scripts/fetch-vendor.sh` 从 `ghfast.top` 拉 tarball（带镜像回退列表）→
  `scripts/build-vendor-frameworks.sh` 用 swift build 交叉编译 device/sim-arm64/sim-x86_64
  三个切片、lipo 合并、手工组装 XCFramework → 主工程静态链接 `Vendor/Frameworks/*.xcframework`。
  首次全流程约 4 分钟，之后构建不入网。
- 宏插件同样被沙箱挡住，全域加 `-Xfrontend -disable-sandbox` 解决。
- GRDB 预编译成二进制后，主工程需显式暴露 `GRDBSQLite` 的 modulemap。

**编码踩坑**：
- 协议扩展里的成员不能充当另一个协议的 witness（`RuleJSONColumn` → `DatabaseValueConvertible` 会报
  "multiple matching properties"），必须给每个类型写显式扩展。
- 上游字段名 `init` 在 Swift 里改名 `initRule`，CodingKey 保留 `"init"`。

**结果**：`BUILD SUCCEEDED`，模拟器安装启动成功，书架页正常渲染。
